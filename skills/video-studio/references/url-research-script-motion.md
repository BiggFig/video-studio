Persist `analysis/research.json` and its completion record before scripting. Facts and image descriptions must refer to the actual supplied evidence. Marketing pages cannot be treated as authenticated product screens. Planned PRD features remain planned. Missing essential proof returns `needs_input`.

Before fresh research and UI documentation, persist structural evidence-readiness reports. Candidate pixels or DOM controls are not proof of a capability. ## Trusted HTML motion

Use the application's bounded `hook`, `brand`, `proof`, `features`, `offer`, and `cta` templates with light/dark scenes and `cut`, `iris`, `lift`, or `expand` transitions. Compile structured data into trusted HTML/CSS with a local font and one paused GSAP timeline. Each rendered frame must be seekable and repeatable. Never execute JavaScript supplied by the model or a source page.

Use the `ui-demo` proof treatment for source-grounded reconstructed workflows. The script schedules pointer movement, typing, clicks, selection and explicit state changes against verified document IDs; trusted components render HTML/SVG elements rather than a screenshot background. Retained source imagery is comparison evidence for quality review. Ordinary showcase/focus/panel proof still uses actual captures or recordings. Unsupported hidden capabilities, prices and customer outcomes remain prohibited. Source-only reference imagery, logos, voices, and soundtrack remain excluded.

Every action uses the same deterministic frame clock. Reserve a readable result hold after the final action. Inspect the exported initial state, each action completion, final hold and seams; compare reconstruction identity and hierarchy with the actual source. A valid file or planned action does not prove that the exported interaction occurred correctly.
