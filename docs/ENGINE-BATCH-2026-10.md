# URL-to-video engine: next delivery batch

The goal is an automatic film that makes its audience, product workflow and outcome understandable while using deliberate composition, motion and sound. The reference studies establish visual targets; manually authored studies and technical export scores do not establish automatic quality.

Each ticket below is an implementation assignment with measurable acceptance. Existing job budgets, evidence checks, runtime identity, private storage and failed reservations remain enforced. New contracts apply to new work; retained jobs must not silently change behavior.

## VS-201 — Research the demonstrable workflow before writing the film

Owner: backend agent. Priority: P0.

Produce a persisted evidence-readiness report: product identity, primary audience, problem, supported action/result, actual UI coverage, observed branding and unresolved gaps. Distinguish observed facts, justified inferences, public marketing imagery and actual product UI. Select a demonstrable workflow; missing essential evidence should yield actionable needs_input before spending on documentation/audio.

Acceptance:
- Valid real-product evidence passes with exact source/fact/asset bindings.
- A marketing-only or unsupported workflow fails with the missing evidence named.
- Prompt injection and unsupported source/state bindings remain rejected.
- Source readiness is retained as inspectable evidence and cannot certify missing inputs.

## VS-202 — Give each film one grounded creative idea and a directed shot plan

Owner: production pipeline agent. Priority: P0. Depends on VS-201.

Persist a creative brief from the verified audience, workflow, outcome and brand. Choose one supported concept such as focus, connection or consolidation in the existing scripting call. Give every scene a specific narrative job and supported motion intent. Avoid generic slogans, repeated proof, decorative transitions and a fixed feature-card sequence. Compile bounded data into the trusted renderer, never generated executable code.

Acceptance:
- Different supported workflows produce eligible, evidence-bound creative choices.
- Current scripts persist their concept and shot intent, and compile into executable direction.
- Fresh directed scripts choose from bounded, source-valid shot recipes that bind the narrative role, fact, asset, template and visual treatment before copy or actions are generated; incompatible combinations and unknown recipe IDs are rejected.
- Unsupported concepts, altered evidence and repair-time identity changes are rejected.
- Legacy completed scripts and plans retain their original behavior.

## VS-203 — Make editable UI documentation reliable within its existing budget

Owner: backend agent. Priority: P0. Depends on VS-201.

Reduce redundant UI response data and focus reconstruction on the actual workflow. Address observed truncation/provenance failures without enlarging model budgets or accepting invented UI. Retain source geometry, recognizable controls, observed text and explicitly illustrative input/state changes.

Acceptance:
- Compact documentation retains required source, capability and state validation.
- Observed text and newly authored sample input are classified correctly.
- Real historical rejection cases receive meaningful regression coverage.
- A fresh automatic URL trial reaches scripting, or records an explicit remaining failure without promoting an invalid response.

## VS-204 — Render designed surfaces, continuous movement and legible outcomes

Owner: interface agent. Priority: P1. Depends on VS-202/203.

Implement the new direction in the production HTML renderer: coherent surrounding materials, independently timed type/object/camera movement and a visible visual motif that connects relevant shots. Follow important controls during actions, then settle into a readable outcome. Preserve documented UI identity and styling.

Acceptance:
- New direction visibly affects real exported frames, not just a prompt or storyboard.
- Motion remains deterministic, bounded and responsive across landscape, square and portrait.
- UI actions and complete result holds remain visible; no hidden source substitution.
- Actual MP4 samples and transitions are visually reviewed; lighting/depth limits are documented honestly.

## VS-205 — Time sound to meaningful events instead of a fixed scene number

Owner: root. Priority: P1. Depends on VS-202/204.

Compile a small sound-cue plan tied to the directed reveal and supported interaction/result events. Reuse the existing generated music and SFX within the current audio-generation allowance. Respect speech, leave quiet moments, avoid repeated sound on every action, and recompile cue timing after an allowed duration repair.

Acceptance:
- Cue frames follow actual compiled events and remain inside the film/source bounds.
- Cues do not interrupt preserved speech or stack too closely.
- Repairs update cue positions without additional audio generations.
- Legacy audio scheduling remains unchanged and existing loudness/speech checks still apply.

## VS-206 — Establish a repeatable URL-to-film quality benchmark

Owner: root, with independent review from the team. Priority: P0. Depends on VS-201–205.

Define a small case matrix covering a public UI-rich product, a different workflow and an insufficient-evidence site. Retain input identity, runtime, stage status, actual usage, delivered file, quality results and observable failure reasons. Separate offline contract/render checks, actual provider-backed URL acceptance, and deployment verification. Include a human comprehension/design rubric instead of inventing an aesthetic score.

Acceptance:
- Benchmark reports cannot label an incomplete run or manual fixture an automatic success.
- At least one fresh bounded URL acceptance is attempted after integration; its exact outcome is retained.
- The report covers audience clarity, demonstrated action/result, source fidelity, composition/materials, continuity, readable holds and sound verification limits.
- Publish only a genuinely verified automatic result; otherwise keep the engine change in draft with the specific blocker and retained output.

## Evaluation order

1. Run focused contract, provenance, budget, timing and retry regressions.
2. Render an integrated fixture through the real HTML/MP4 path and inspect meaningful action frames and seams. A fixture verifies mechanics only.
3. Run a fresh URL through capture → research → UI documentation → creative script → picture → audio → quality within the configured ceiling. Do not resume old failed jobs under new code.
4. Review the actual film for comprehension and design separately from export integrity. A technically valid film may still need creative work.
5. Keep deployment and production-private-storage claims separate from local acceptance. Merge/release only what its evidence supports.

Later work, outside this bounded batch: physical 3D/refraction, generated narration, listener studies, and broad claims of outperforming agency films. Those need their own assets, budgets and evaluation.
