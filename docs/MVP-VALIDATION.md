## Reproduction

`npm test` runs offline/security tests. To run the isolated database and private storage integrations, set `STUDIO_DB_INTEGRATION=1` or `STUDIO_STORAGE_INTEGRATION=1`, load the project's `.env.local`, and run the corresponding test with Node and `--import tsx`. They create temporary test records/objects and clean them afterward.

`npx tsx worker/smoke-render.ts --out .worker-smoke` runs the actual renderer using clearly synthetic sources. Its output folder is ignored by Git and Vercel. `worker/smoke-sandbox.ts` repeats the renderer test and the three real-PDF reader tests in the configured snapshot, subject to explicit source-upload authorization. It uploads the worker modules and required fixtures, excluding unrelated tests, and retains Linux PDF output alongside render evidence. Its source is prepared and typechecked; no cloud execution is claimed. No test sets a customer job to ready using fixture results.

Set `STUDIO_INGEST_INTEGRATION=1` and run `npx tsx --test worker/ingest.test.ts` to exercise the local media/browser/network failure cases. This requires FFmpeg/FFprobe and installed Playwright Chromium. The tests deliberately never call paid providers. PDF parser stubs are labelled and do not certify real Poppler behavior.

Set `STUDIO_PDF_INTEGRATION=1` and run `node --import tsx --test worker/pdf-ingest.test.ts` for the separate real-document tests. Put an actual `pdftotext` on PATH or set `PDFTOTEXT_PATH` to its absolute path. The local verified executable was `C:\Program Files\Git\mingw64\bin\pdftotext.exe` (Xpdf 4.00). These tests create and remove confined synthetic fixtures, exercise the default reader command without injection, and enforce a 15-second subprocess deadline. Run them against the cloud Poppler executable as part of authorized worker verification.

The earlier toolkit validation is preserved in [VALIDATION.md](VALIDATION.md). It concerns the original broader toolkit and must not be interpreted as certification of the new SaaS pipeline.
